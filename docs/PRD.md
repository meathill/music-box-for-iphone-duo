## 1. 一页纸摘要

**一句话：** 一台会随着手机折叠而打开、唱歌、合上就睡的八音盒。

> 打开，它就唱。合上，它就睡。
> *Open it, it sings. Close it, it sleeps.*

**为什么能被推荐（我们的判断，不是 Apple 的承诺）：**

1. **折叠是体验本身，不是适配。** Apple 在 2026-10-22 的新闻稿里专门点名了"把折叠变成玩法"的独立 App（Deck-Man：打开选专辑、合上开始听），点名了半折立放场景（Flighty、Tiimo、NYT Cooking、MLB）。八音盒的"盖子 = 铰链"是同一类、而且更直觉的映射。
2. **用到的是 Duo 独有的连续信号，不只是开 / 合。** iOS 27.1 的铰链 API 提供连续角度。我们让**盖子角度同时驱动画面（开盖）、音色（低通滤波打开）、速度（合盖时的渐慢）**。Apple 自己的演示是用铰链角度做吉他的 pitch bend，思路相通。
3. **每一个姿态都有意义。** 外屏 = 合着的盒子；半折立放（床头）= 盒子打开在唱歌；完全展开 = 纸带编辑器。
4. **完整的工艺。** 采样音色、物理动画、Core Haptics、120Hz、无障碍、4 语言、无账号、离线。这是 ADA 评语里反复出现的那一类东西。
5. **时机。** Duo 2026-10-23 首批发货，新闻稿说 App Store 上有专门的 Duo 编辑专题和 "Made for iPhone Duo" 徽章。窗口期就是最近几个月。

**我们明确不做什么：** 账号体系、社交广场、订阅、广告、通用音乐播放器、AI 生成曲子（首版）。

**路线（详见 §9）：**

| 阶段 | 目标 | 目标日期（建议） |
|---|---|---|
| M0 | 验证：渲染 120fps、音频抖动、铰链行为 | 2026-11-08 |
| **M1** | **视频版 MVP：开盖 / 一首公版曲 / 合盖即停**，用于小红书活动 | **2026-11-15** |
| M2 | P0 全功能 Alpha | 2026-12-13 |
| M3 | TestFlight 公测 + 打磨 | 2027-01-08 |
| M4 | 提交审核；**提交推荐提名**（≥3 周前，建议 4 周） | 2027-01-08 提名 / 2027-02-02 上线 |
| M5 | 发布后迭代（小组件、分享网页、哼唱成曲） | 2027-02 之后 |

### 2.4 现实的预期（请放在心上）

- Duo 起价 ¥15,999，**装机量在早期会很小**。所以这个 App 的首要目标是"被编辑看见 + 小红书传播"，**不是营收**。非 Duo 的 iPhone 上也必须好用，这样才有长尾。
- 编辑推荐是 Apple 编辑的决定，**没有任何做法能保证**。本 PRD 的做法是把概率拉高。

## 3. 产品定位、原则、范围

### 3.1 定位

**为折叠屏而生的、可以自己编曲的八音盒。** 摆在床头，是夜灯、是闹钟、是摇篮曲。

### 3.2 体验原则（评审任何设计 / 实现时用）

1. **折叠就是遥控器。** 铰链角度是一等输入，每一次开合都有对应的画面、声音、触觉。
2. **一个主角，一个动作。** 每个姿态只有一个视觉主角（开着的盒子 / 合着的盒子 / 纸带），只有一个主要动作（上发条 / 点开 / 打孔）。
3. **视觉、声音、触觉同帧。** 任何一次"发生"，三者在同一帧内发生（允许 ≤ 10ms 的校准偏差）。
4. **物理可信。** 速度、重量、摩擦、渐慢，都按真实机械来。没有不可解释的魔法。
5. **不把功能绑在姿态上。** Apple 的明确要求（Tech Talk 111466）。**每个由铰链触发的交互都有触摸等价操作**；非 Duo 的 iPhone 拿到的是完整产品。
6. **安静。** 无广告、无弹窗催评、无打卡、无推送营销。睡前产品尤其如此。
7. **零说明。** 引导 ≤ 3 步，靠"开盖 → 摇钥匙 → 听"自然学会（ADA 评语：不用读说明就能玩）。

### 3.3 范围（一句话）

- **做：** 八音盒场景、铰链驱动、发条、采样音色、公版曲库、纸带编辑器（15 / 20 / 30 音）、闹钟、睡眠循环、分享、小组件 / 灵动岛、4 语言、无障碍。
- **不做（首版）：** 账号、云同步、社区广场、流行歌曲库、AI 作曲、Android 版、iPad 专项适配、Apple Watch。
- **之后再做：** 哼唱成曲、可打印纸带 PDF（含校准尺）、更多箱体包。

### 3.4 目标用户与场景

| 场景 | 用户 | 姿态 | 关键动作 |
|---|---|---|---|
| S1 睡前 | 想要安睡的成年人 / 给孩子放摇篮曲的家长 | **半折立放在床头** | 打开 → 上发条 → 睡眠定时 → 灯慢慢暗下去 |
| S2 把玩 | 买了 Duo 的科技爱好者、小红书看到视频的人 | 任意 | 反复开合，看盖子、听音色 |
| S3 创作 | 想给朋友 / 孩子做一首曲子的人 | **完全展开** | 在纸带上打孔、试听、分享 |
| S4 起床 | 想被温柔叫醒的人 | 睡前设置，早晨系统闹钟界面 | 选曲 → 设时间 |
| S5 口袋里 | 在外屏上随手玩一下 | **合着（外屏）** | 点盖子，听一小段 |

## 4. 信息架构

整个 App 只有**一个主舞台（Stage）**加几个底部半屏（Sheet），没有 Tab 栏：

```
Stage（主舞台，随姿态变形）
 ├─ 盒子场景：盖子 / 滚筒 / 梳齿 / 发条钥匙 / 铭牌
 ├─ Sheet：曲库（Songs）
 ├─ Sheet：闹钟（Alarm）
 ├─ Sheet：睡眠（Sleep）—— 定时、夜灯、合盖行为
 ├─ Sheet：分享（Share）
 ├─ Workshop（纸带编辑器）—— 完全展开时占据主舞台；其他姿态下作为全屏页进入
 └─ Settings（触觉、动效、音量上限、语言、关于）
```

用系统的 `Stack` 与原生 Sheet，系统会处理竖向栏和折痕避让（Expo 官方建议"让 iOS 画导航"）。

## 5. 平台能力核实表（最重要的一章）

> 状态：**已核实** = 我读到了 Apple / Expo 官方原文；**部分** = 有官方来源但细节缺失；**未核实 / 假设** = 我没有找到来源，设计上按"假设成立，但有回退"处理。**这里没有编造 API 名称。**

### 5.1 铰链与布局（iOS 27.1）

| 能力 | 结论 | 来源 | 状态 |
|---|---|---|---|
| 铰链 API | SwiftUI：`onHingeChange`；UIKit：`UIHingeInteraction`。给出状态（`closed` / `partiallyOpen` / `fullyOpen`，UIKit 另有 `unknown`）和**连续角度**。`hinge` 为 `nil` 表示设备没有铰链。 | Apple Tech Talk 111464 | 已核实 |
| 角度单位 | SwiftUI 为 `Angle`（平放 = 180°）；UIKit 为弧度。Expo 的 `expo-hinge` 统一为**度，0 = 合上，180 = 平放** | 社区示例、Expo 文档 | 已核实 |
| 用途限制 | **铰链用于交互与效果，布局用 arrangement / reserved regions。** 角度更新的频率和精度是**系统策略**，不能依赖。 | Tech Talk 111464；社区示例"Good to Know"（模拟器观察，非官方保证） | 已核实 |
| 布局 API | Reserved regions（`division` 折痕、`occlusion` 摄像头）、`ArrangementView`（`.split` / `.overlay`）、竖向栏（toolbar / tab bar 变竖） | Apple 新闻稿、Tech Talk 111463 | 已核实 |
| 折痕尺寸（模拟器观察） | division 区域 40pt 宽，两侧各 20pt margin；仅半折时 active | 社区示例，**非官方保证** | 部分 |
| 竖向栏 inset | 约 84pt（左或右） | Expo 官方指南 | 已核实 |
| 外屏行为 | 合上后应用回到外屏（compact 宽 × regular 高）；外屏没有 reserved regions；外屏也有竖向栏 | Apple "Prepare" 页；社区示例（模拟器观察） | 已核实 / 部分 |
| **合上时应用是否继续前台运行、铰链是否报告 `closed`** | Apple 说"合上后应用回到外屏"，Expo 文档说 iOS 上通过 `UIHingeInteraction` 取值。**但我没有找到明确说明"应用在外屏上时 `closed` 一定被送达"的文字。** | — | **未核实 → M0 必须真机验证** |
| 外屏上显示附属内容 | 我只找到 `CameraCaptureAccessory`（相机类 App）和 `ExternalNonInteractiveAccessory`（外接显示器）。**没有找到面向音乐 / 一般 App 在外屏放附属内容的 API。** | Tech Talk 111464、社区示例 | **未找到 → 不依赖** |
| 全天候显示（AOD） | **没有找到第三方 App 在 AOD 状态绘制画面的 API。** | — | **未找到 → 假设用 Live Activity / 锁屏小组件的"降低亮度"样式** |
| 模拟器 | Xcode 27.1 的 **Device Hub** 可开 / 合 / 折 / 转 Duo；StandBy 和多数 App Extension 在 Duo 模拟器里不可用 | Apple 新闻稿、Expo 指南 | 已核实 → **小组件 / Live Activity 要真机** |

## 6. 体验设计（本 PRD 的核心）

### 6.1 品牌与感受

- **关键词：** 温暖 · 手作 · 安静 · 精密 · 一点点魔法。
- **一天中的三种光：** 白天（米色纸 + 浅木）、黄昏（琥珀）、夜晚（深核桃木 + 台灯暖光）。**默认跟随系统外观 + 当前时间自动切换**，睡眠模式固定为夜晚。（对应 ADA Tide Guide 评语"配色跟着天空走"的思路。）
- **声音性格：** 玻璃与金属的清脆，带一点点木箱的暖。不用电子合成器音色。
- **语气：** 短句、温柔、有一点点俏皮，不说教（见 §6.10 微文案）。

### 6.2 视觉语言

#### 材质

| 材质 | 用在哪里 | 画法 |
|---|---|---|
| **核桃木**（深） | 盒身、盖子外侧、底座 | 预渲染木纹贴图（Blender）+ Skia 着色器叠加方向性高光；盒角做**指接**（参考 Dribbble #1） |
| **黄铜** | 发条钥匙、铭牌边框、铰链条、梳齿固定螺丝、棘轮 | 预渲染底色 + 运行时 SkSL 做各向异性高光，高光随灯光和（Duo 之外）陀螺仪微移 |
| **钢**（梳齿、滚筒） | 梳齿、滚筒、打点 | 冷色高光，与黄铜形成冷暖对比 |
| **米色手工纸** | 纸带、曲目标签 | 带纤维噪点；孔洞有**内边阴影**和被打穿的白色纸边 |

### 6.3 姿态与布局

**原则：** 只针对两类尺寸设计——**外屏 compact 宽度**、**内屏 regular 宽度**；**不用设备方向，不用写死的尺寸**（Apple "Prepare" 页）。姿态由三类信号共同决定，**各管一摊**：

| 信号 | 管什么 | 来源 |
|---|---|---|
| 窗口尺寸 / size class | **布局**（单栏 / 双栏） | `useWindowDimensions`、`onGeometryChange` |
| 折痕区域（reserved region `division`） | **布局**（避开折痕、上 / 下或左 / 右分区） | `react-native-reserved-regions` |
| 铰链角度与状态 | **效果**（盖子角度、音色、渐慢、视差） | `expo-hinge/reanimated` |

> 这样做是遵守 Apple 的明确指引：铰链数据用来做交互与效果，不用来做布局。

#### 姿态矩阵

| 姿态 | 判定 | 画面（主角 / 动作） | 控件位置 |
|---|---|---|---|
| **A 外屏·合着** | 窗口 compact 宽；铰链 `closed`（或铰链未知但窗口为外屏尺寸） | 合着的盒子，铜扣微微反光。**点盖子 = 掀开**（触摸等价） | 竖向栏由系统放；我们只在盖子上做一个手势 |
| **B 桌面立放（主打）** | `partiallyOpen` 且折痕为**水平带**（上下分区） | **上半区**：盖子打开，滚筒转、梳齿拨、铭牌。**下半区**：钥匙、播放、曲目、睡眠。折痕处画成**黄铜铰链条**（纯装饰，不放可点元素） | 可点元素只放在下半区；折痕带内无可点元素 |
| **C 书本式半折** | `partiallyOpen` 且折痕为**竖直带**（左右分区） | **左页**：盒子；**右页**：控件和曲目（按 Apple 指引：控件靠后侧、靠近合上时的外屏） | 折痕两侧各留 ≥ 20pt |
| **D 完全展开** | `fullyOpen`，regular 宽 | **工作台**：用 `ArrangementView`，主区 = 纸带编辑器，副区 = 缩小的盒子（实时看滚筒转）。盖子"向后放平" | 控件在竖向栏 + 底部工具条；纸带跨折痕不需要避让（连续内容不位移） |
| **E 普通 iPhone / 窄窗口** | 无铰链（`hinge == null`）或窗口 compact | 单栏：盒子占上 55%，控件占下 45%；**盖子用手势掀开**（拉铜扣向上） | 常规底部区域 |
| **F Split View** | 窗口宽 ≈ 469pt（Expo 文档数字） | 同 E | 竖向栏在窗口外沿 |

**判定"水平带 / 竖直带"：** 读 `division` region 的 `frame`，`width > height` 为水平带。**不要用 `UIDevice.orientation`。** Tent（靠边缘倒 V 立放）姿态下内屏可见哪一部分，我没有核实，Device Hub 里确认后并入 B 或另列。

**姿态切换动画：** 布局切换用统一的 **`emphasized` 480ms**（见 §6.5），元素用"位移"（displacement）而不是淡入淡出——盒子从上下分区移到左右分区时，**同一个元素移动过去**，保持关联（Apple Tech Talk 111463）。

**折痕避让细则：**
- 折痕 active 时，可点元素不放进 division frame（+ margin）。
- 折痕 inactive（完全展开）时，用 `includeInactive` 读取，**预先**按折痕位置布局，避免用户折起来时画面跳动（社区示例的建议）。
- Reserved regions 在首次布局后才到达，**不要缓存**，在渲染里读取。

### 6.5 动效规范

#### 全局 Token（初始值，需真机调）

| Token | 时长 | 用途 |
|---|---|---|
| `instant` | 90ms | 按下反馈 |
| `quick` | 160ms | 小控件状态 |
| `standard` | 280ms | 常规转场 |
| `emphasized` | 480ms | 姿态切换、Sheet |
| `ceremonial` | 720ms | 开盒仪式、合盖仪式 |
| `ambient` | 2–8s | 呼吸光、粒子漂浮 |

**缓动曲线（cubic-bezier）：**
- `decelerate` = (0.2, 0, 0, 1)：进入、展开
- `accelerate` = (0.3, 0, 1, 1)：退出、收起
- `mechanical` = (0.4, 0, 0.2, 1)：机械件的位移

**弹簧**（Reanimated `withSpring` 参数；`ζ = damping / (2·√(stiffness·mass))`）：

| Token | mass / stiffness / damping | ζ | 过冲 | 用途 |
|---|---|---|---|---|
| `spring.lid` | 1 / 140 / 18 | 0.76 | ≈ 2.5% | 盖子：像带阻尼的铰链，几乎不过冲 |
| `spring.key` | 1 / 220 / 14 | 0.47 | ≈ 18% | 钥匙回弹：棘轮感，有一点弹 |
| `spring.chip` | 1 / 400 / 28 | 0.70 | ≈ 5% | 通用小控件 |
| `spring.settle` | 1 / 90 / 20 | 1.05 | 0 | 无过冲的安顿（睡眠、减少动态效果下的替代） |

> 过冲 = `exp(-π·ζ / √(1-ζ²))`，仅 ζ < 1 时。

**帧率目标：** 播放与交互期间 **120fps**（帧预算 8.33ms，UI 线程 ≤ 5ms）；睡眠模式 ≤ 30fps（省电）；静止可降到按需渲染。

#### 逐个转场

**T1 开盒（冷启动 → 舞台）** · `ceremonial` 720ms
- 画面：黑场 → 台灯光斑从中心亮起（`decelerate` 400ms）→ 盒子从微暗中浮现，轻微放大 0.96→1.0（`spring.settle`）。
- 声音：一声极轻的木头"嗒"。
- 触觉：无（避免冷启动打扰）。
- 目标：**冷启动到可交互 ≤ 1.2s**；仪式动画不阻塞交互，用户可在 300ms 后就开始操作。

**T2 开盖（铰链驱动）** · 连续
- **输入：** `useAnimatedHinge()` 的角度 θ（0 合 … 180 平）。
- **映射（初始值）：** 盖子打开度 `L`：θ ≤ 8° → 0；θ ≥ 95° → 1；之间按 `smoothstep` 映射。
- **平滑：** 铰链更新的频率和精度是系统策略，**不能直接绑定**。把 `L` 作为目标，用 `spring.lid` 追，**即使两次更新间隔 100ms，画面也连续**。
- **画面：** 盖子绕后沿旋转 0→约 100°；盖子内衬（丝绒红）逐渐可见；盒内光从缝里渗出，随 `L` 增亮；**盒内台灯光斑随 `L` 扩大**。
- **声音：** 同一个 `L` 驱动低通滤波截止频率：`cutoff = lerp(900Hz, 16kHz, L^0.6)`，增益 −6dB→0dB（时间常数 80ms 平滑）。盖子越开，声音越"亮"。
- **触觉：** 开盖越过 `L=0.5` 时一个很轻的"咔哒"（transient 强度 0.3 / 锐度 0.6）；**不要和铰链本身的物理手感打架**，保持克制。
- **回退（无铰链）：** 拉铜扣向上，手势位移映射到同一个 `L`，同样的弹簧。

**T3 上发条** · 手势 + 机械
- **手势：** 钥匙是一个旋转手柄。圆周拖动（顺时针）转动钥匙；每 15° 一个棘轮齿。**也支持"按住钥匙"自动上发条**（给不方便做圆周手势的人，也是无障碍等价操作）。
- **画面：** 钥匙转动 + 弹簧盒（盒内的发条圈）压缩的视觉暗示（小圆盘上的螺旋收紧）；发条余量 `W∈[0,1]` 用铭牌下一条黄铜细线表示。
- **回弹：** 松手后钥匙随着发条释放缓缓反转，`spring.key`。
- **声音：** 棘轮"嗒嗒嗒"（颗粒式：每齿一个采样，音高随余量略升）。
- **触觉：** 每齿一个 transient（强度 0.5 / 锐度 0.8）；上满时（`W=1`）一次强 transient（0.9 / 0.4）接一个 60ms 的短连续震。
- **时长规则：** 每圈约 60 秒演奏时长，最多 5 圈（初始值）。"永动"模式（用于睡眠）无限。
- **"开盖就唱"（设置，回访用户默认开）：** 开盖到 `L>0.8` 后，**钥匙自己转一圈**（700ms，带棘轮声）然后开始演奏——"打开，它就唱"，但仪式仍然可见。首次使用必须手动上发条（引导步骤 2）。

**T4 滚筒转动与梳齿拨动（演奏中）** · 与音频同步
- **单一时钟：** 所有视觉由 `musicTime` 驱动，`musicTime` 来自音频时钟（`AudioContext.currentTime`，减去输出延迟）。**画面跟随音频，不是反过来。** JS 到 UI 线程的时钟传递方式见 §8.4「时钟传递」（需验证）。
- **滚筒：** 一首曲子 = 滚筒转一圈。角度 `φ = 2π · t / T`（T = 曲长 + 尾静默）。画法：把滚筒表面当作一张横向展开的纹理，用 `x' = R·sin(φ)` 做圆柱投影，亮度随 `cos(φ)` 衰减（背面变暗）。
- **打点（销钉）：** 位置由音符 `(t, 音高)` 决定。销钉扫过 `φ=0` 的一刻正好拨到对应的梳齿。
- **梳齿拨动：** 每个齿是一个阻尼振子：`y(t) = A · e^(−t/τ) · sin(2π f_v t)`，**视觉频率** `f_v` 取 14–30Hz（低音慢、高音快；真实音频的几百到几千 Hz 看不见，也会在 120fps 下混叠），`τ ≈ 220ms`，`A ≈ 2.5pt`（力度 × 1.0–1.6）。相邻齿加 ±8% 随机相位，避免整齐划一。
- **余音：** 被拨的齿旁边有一个很淡的"音波"光点，向上飘 8–12pt，300ms 淡出（`ambient`）。
- **机械件：** 棘轮、调速轮转速随曲速；调速轮可见，用于渐慢时的反馈。
- **性能：** 同时可见的销钉 ≤ 80；齿 ≤ 30；不为每个销钉建独立视图，用一次绘制调用（Skia `drawAtlas`）。

**T5 曲目切换（换滚筒）** · `emphasized` 480ms + 声音
- 手势：下半区"曲目转盘"左右拨动；点击曲名也可。
- 画面：当前滚筒向上被"取出"（上移 + 淡出 + 轻微放大 1.04，`accelerate` 200ms），新滚筒从下方"装入"（`decelerate` 280ms，`spring.chip`）；铭牌文字做 120ms 的**纸标签翻页**。
- 声音：金属"咔"（取出）与"嗒"（装入），各 1 个采样。
- 触觉：取出时 transient 0.4 / 0.4；装入时 0.6 / 0.5。
- 若正在演奏：旧曲**先渐慢停止**（缩短版的合盖渐慢，400ms），再切换，新曲不自动播放（除非"一直转"开启）。

**T6 合盖（渐慢仪式）** · 事件触发 + 连续
- **触发：** 播放中，铰链角度**向下穿越 40°** 时启动（按事件触发，不依赖更新频率）。
- **渐慢（ritardando）：** 速度因子 `f` 从 1.0 在 **900ms** 内降到 0.45，采用 `ease-in`（二次）——像发条松了。**音高不变，只拉长音符间隔**（真实八音盒就是这样）：音符由我们的调度器逐个安排，改间隔很简单。滚筒、调速轮同步变慢。
- **同时：** 低通截止随 `L` 一起降低（T2 的映射），所以声音在变慢的同时"被盖住"。
- **停止：** 铰链 `closed`（或 θ ≤ 5°）时：最后一个音自然衰减（尾音 1.2s，低通从 8kHz 扫到 1.2kHz，600ms），然后静音。
- **盖合：** 盖子完全合上的一瞬，铜扣"咔"一声（采样 + 触觉双击：0.8/0.5，70ms 后 0.4/0.2）。
- **反悔：** 如果在渐慢过程中又打开（θ 回升到 > 50°），取消停止，`f` 用 `spring.chip` 在 400ms 内回到 1.0。
- **外屏接管：** 合上后应用回到外屏，显示 A 姿态（合着的盒子），状态保持。
- **"合盖行为"设置：**
  - 默认 **停止**（符合"合上它就睡"）。
  - **闷音继续**（睡眠用）：合盖后音乐不停，但低通固定在 ≈ 900Hz、音量 −6dB，像隔着盖子听；睡眠定时照常淡出。

**T7 完全展开 → 工作台** · `emphasized` 480ms
- 触发：状态变为 `fullyOpen` 且窗口 regular 宽（**布局信号**，不是角度）。
- 画面：盖子"向后放平"（`spring.lid`，旋转到 180° 并滑出画面上沿）；盒子缩小到副区（位移，不是淡入淡出）；**一条纸带从盒子的梳齿下方"抽出"**，铺满主区（`decelerate` 400ms，纸带前端带轻微卷曲）。
- 声音：纸张滑动的细微"沙"（0.5s）。
- 触觉：无。（用户已经在大幅度动手，别叠加。）
- **反向**（半折回来）：纸带被"吸回"盒子，盖子立起，回到姿态 B / C。

**T8 打孔 / 擦除 / 试听（编辑器）** · 即时反馈
- **打孔：** 点击或拖动纸带上的格子。打孔器（小黄铜冲头）从上方落下，`instant` 90ms；孔位出现**内阴影 + 白色纸边**；**2–3 个纸屑**从孔位弹出，受重力下落，220ms 淡出。
- **声音：** 柔和的"咚"（打孔）+ **对应音高的梳齿声预览**（让人知道打的是哪个音）。
- **触觉：** transient 0.7 / 0.3，接 40ms 连续 0.2（"咔嚓"）。
- **擦除：** 孔被"补上"——纸屑反向飞回，transient 0.3 / 0.2。
- **播放头：** 固定在纸带的某一处（梳齿位置），**纸带从右向左穿过**（由 `musicTime` 驱动）。
- **两音太近：** 15 / 20 / 30 音机芯同音间隔过近会弹不出（前序调研已记录）；违反时孔位**轻微变红**（同时有形状标记，不单靠颜色），振动 `notification warning`。
- **选择与精度：** 30 行在内屏上每行约 22pt，小于 44pt 点击目标。方案：打孔使用"**放大镜预览 + 吸附到最近行**"；纸带可以**纵向缩放**（捏合）；同时提供**列表模式编辑器**（无障碍与精确输入共用，见 §6.8）。
  > 内屏点数尺寸是按 Duo 内屏截图像素 2007×2853、**假设 3× 缩放**得出约 669×951pt，**待在 Device Hub 里实测确认**。

**T9 拨盘（闹钟 / 睡眠定时 / 发条圈数）** · 统一语言
- 白色（或黄铜）旋钮 + 刻度环 + 红色指示点（参考 design-references #14、#15）。
- 刻度间隔每 5 分钟一格；越过整刻度时 `UISelectionFeedback` 类轻触觉（用自写模块实现更细腻的 transient 0.25 / 0.7）与"嗒"声。
- 惯性：松手后用 `withDecay`（速度衰减 0.998 / 帧）并吸附到最近刻度（`spring.chip`）。

**T10 睡眠（渐暗）** · 长时程
- 开始：台灯光斑 `ambient` 缩小；盒内光变暗；滚筒仍在转，但**降到 10fps 渲染**（省电，肉眼上像"慢动作的呼吸"）。
- 定时最后 **60 秒**：音量按三次曲线淡出，同时速度因子缓降到 0.7（"发条走完"的感觉）；结束时自动合盖动画（盖子缓缓落下 3s）并停止。
- 屏幕：**不强制常亮**；用户可在设置里开"保持唤醒"。自动锁屏后，音频靠后台音频继续，灵动岛 / 锁屏显示正在播放。

**T11 分享** · 15s 视频与卡片
- 卡片：纸带被"折"成一张小卡片（翻折 3 段，每段 160ms），带曲名和你的署名（可选）。
- 视频（P0）：App 内用同一套渲染 + 音频离线合成，导出 15s 竖版 / 横版视频。

**T12 灵动岛 / 锁屏 / 小组件 / 外屏常亮**
- **灵动岛（Live Activity）：** 紧凑态：左 = 小圆柱图标，右 = 剩余发条细线；展开态：曲名、播放 / 暂停（P1 才有按钮）。Duo 上灵动岛会变成竖向，占用栏位空间（Expo 指南说明），**内容要极简**。
- **锁屏 / "全天候显示"：** 我没找到第三方 App 在 AOD 下绘制画面的 API（§5.1）。**做法：** 用锁屏小组件 + Live Activity，读取"降低亮度"环境值（`isLuminanceReduced`），降低亮度时：黄铜换成**描边**，去掉填充。
- **主屏小组件：** `systemSmall` 下一个闹钟（时间 + 曲名）；`accessoryCircular / Rectangular` 锁屏版。**不能有动画**（小组件限制）；盒子"转"的感觉靠 **最多 4 张静帧 + 时间线**，不要强行模拟。

**T13 无铰链回退总表**
| 铰链驱动的交互 | 触摸等价 |
|---|---|
| 开盖（T2） | 向上拉铜扣；点外屏盖子 |

### 6.6 触觉规范（Core Haptics）

**原则（来自 Apple HIG "Playing haptics"）：** 只用于强化清晰的因果；短、一致、可关闭；与视觉和声音协调。

**原则补充（我们自己的）：**
- **节奏规则：** 演奏时**只给"低音声部 / 强拍"配触觉**，每秒最多 6 次，否则会麻、也会"糊"。
- **同步：** `CHHapticEngine.currentTime` **不等于**音频时钟。做法见 §8.4：预生成每首曲子的触觉图案，以绝对时间戳启动，并在真机上用一次"闭环校准"（麦克风听音 + 加速度计测震）求固定偏移。
- **开关：** 设置里可关；系统"触感"设置关闭时全部不触发；低电量模式下减半。

| 事件 | 触觉 | 强度 / 锐度 | 时长 | 说明 |
|---|---|---|---|---|
| 开盖越过 50% | transient | 0.3 / 0.6 | — | 克制 |
| 钥匙每个棘轮齿 | transient | 0.5 / 0.8 | — | 每 15° |
| 发条上满 | transient + continuous | 0.9 / 0.4 + 0.3 / 0.2 | 60ms | |

### 6.7 音频规范

#### 音色来源（按优先级）

1. **实录**（强烈建议，也是最能拉开差距的地方）：买一台质量好的 30 音机芯，在安静的房间、双麦克风、96kHz / 24bit 录制。**每个齿单独拨**（用销钉工具，避免滚筒噪声）。
   - 每个齿 **3 个力度层 × 2 个轮换样本**（round-robin）= 180 个样本，每个约 1.5–2.5s，处理后约 **25MB**（压缩后）。
   - 另录机械声：棘轮上弦、发条运转（低电平循环）、调速轮、铜扣"咔"、盖子开合的木头声。
2. **建模补全**：超出实录音域的音，用模态合成补：悬臂梁的泛音比约为 **1 : 6.27 : 17.55**（非谐泛音，这是金属齿"叮"的来源），衰减时间依次约 1.8s、0.5s、0.12s（初始值，对照实录调）。

> **自己录，或买有明确商用授权的采样。** 不要用来源不明的采样（版权风险）。

#### 实际音高表

- 30 音机芯的纸带**印刷音名与实际发声不一致**（前序调研已记录：真实音高从下到上为 F3、G3、C4…A6，共 30 个）。编辑器里提供"印刷音名 / 真实音高"双显示。**这张音高表来自网上社区资料，必须用你买的实物机芯校准后才能定稿。**

#### 箱体材质（混响 / 均衡）

| 箱体 | 混响 RT60 | EQ | 其他 |
|---|---|---|---|
| 核桃木（默认） | 0.35s | 700Hz 附近 +3dB（Q 1.2，箱腔共鸣）；6kHz 高架 −2dB | 暖、短 |
| 黄铜 | 0.8s | 5kHz 高架 +2dB；2.8kHz 窄峰（Q 8）带 0.6s 金属余振 | 亮、长 |
| 纸盒（礼品盒） | 0.15s | 7kHz 低通 | 干、近 |

实现：卷积混响（短脉冲响应，建议自制，约 0.3–1.0s）+ 双二阶滤波。**盒盖开合是一个额外的低通**（T2）。

#### 渐慢与机械声

- 速度因子 `f` 只改音符间隔，不改音高。
- 机械声层：运转声 −34dBFS，随 `f` 变速；上弦棘轮声颗粒化；停止时一声很小的"嗒"。

#### 响度与安全

- 峰值 ≤ −3dBFS；睡眠模式默认再 −6dB；音量上限设置（默认不限制系统音量，但提供"睡眠安全音量"）。
- 淡出：最后 60 秒，三次曲线。
- **插拔耳机 / 切换输出：** 先渐慢到停（400ms），不要突然断。
- **静音开关：** 我们是"播放类"音频，不受静音开关影响；**闹钟由系统 AlarmKit 负责**。

#### 闹钟音频

- 用 App 自己的调度器把用户的曲子**预渲染**成一个文件，放在 `Library/Sounds`，交给 AlarmKit。
- "温柔唤醒"曲线：前 8 秒极轻、只有单音，随后加入更多音符并逐步变亮（低通上移），像天亮。**时长上限未核实（§5.2）**，M0 测。
- 预渲染需要离线渲染：`react-native-audio-api` 是否提供 `OfflineAudioContext` 我**未核实**；回退方案是写一个 Swift 模块，用 `AVAudioEngine` 的离线渲染模式。

### 6.8 无障碍

| 项 | 要求 |
|---|---|
| **VoiceOver** | 盖子：`adjustable`，朗读"盖子，已打开 / 已合上"，增减 = 开合。钥匙：`adjustable`，增减 = 发条 ±1 圈（无需圆周手势）。铭牌：朗读曲名。曲库：列表，选中即切换。**合盖 / 开盖这种由铰链触发的状态变化不逐次朗读**（避免噪音），只在状态确实影响用户时（如"音乐已停止"）用 `polite` 播报。 |

| **减少动态效果（Reduce Motion）** | 去掉弹簧过冲、纸屑、视差、光斑缩放；盖子用 **250ms 淡入淡出（3 个关键帧交叉淡化：合 / 半开 / 开）**；滚筒仍转，但**降低到慢速且去掉模糊**；梳齿拨动改为"被拨的齿高亮 150ms"。**铰链驱动仍然工作**（那是用户的物理动作），但画面用交叉淡化而不是连续形变。 |
| **减少透明度 / 增强对比度** | 铭牌改为纯色底 + 高对比文字；去掉暗角；对比度 ≥ 7:1。 |
| **不单靠颜色区分（Differentiate Without Color）** | 打孔 = 孔洞形状；冲突音 = 形状标记（小三角）+ 颜色；选中 = 轮廓线 + 填充。 |

| **粗体文本** | 响应系统。 |
| **触觉替代** | 触觉开关；所有触觉反馈都有声音和视觉对应。 |
| **听觉** | 滚筒销钉、梳齿高亮可视；"闪烁"提示开关（闹钟设置成功等）。 |
| **运动敏感** | 睡眠模式不使用快速运动；滚筒最大角速度限制（< 45°/s）。 |
| **App Store 无障碍标签** | 如实填写 App Store Connect 里的无障碍声明（字段名以当前 ASC 为准，我没有核实）。 |

### 8.2 渲染：Skia vs 其他（决策与理由）

| 方案 | 优点 | 缺点 / 风险 | 结论 |
|---|---|---|---|
| **A. `@shopify/react-native-skia` + 预渲染精灵 + SkSL 着色器**（2.5D） | 在 UI 线程直接被 Reanimated 共享值驱动；单个 Canvas 内混合位图、矢量、着色器；120fps 现实可达；包体可控；与 RN 手势和无障碍层容易叠加 | 不是真 3D；"圆柱"靠圆柱投影 + 贴图；需要美术用 Blender 预渲染高质量素材 | **采用（首选）** |
| B. React Three Fiber（three + `expo-gl`） | 真 3D、PBR 光照最好 | 包体增加；与 Reanimated 工作线程协作复杂；文本 / 手势 / 无障碍要另做；对新版 RN 的兼容性我**未核实**；3D 资产管线成本高 | 不采用（除非 A 的 M0 验证失败） |
| C. Rive | 设计师可视化做状态机，输入可绑定数值（角度） | 梳齿的阻尼振动、销钉位置由乐谱驱动，难以数据驱动；运行时与新架构的集成状态我**未核实** | 仅作为小图标 / 引导动画的候选 |
| D. 原生 SceneKit / RealityKit 视图（Expo 原生模块） | 最高保真度，真 3D | 违背"RN 为主"；调试成本高 | **逃生通道**：如果 M0 里 A 达不到质量或帧率，只把"盒子舞台"换成原生视图，其余仍是 RN |

**A 方案的美术管线（要点）：**
- Blender 渲染（Cycles）：**盒身（木）、盖子（含 0–100° 的 24 帧序列）、钥匙、铭牌底板、纸带纤维、销钉高光贴图**。盖子的 24 帧用**精灵图集**，按 `L` 取帧并插值，避免实时几何。
- 运行时（Skia）绘制：滚筒（圆柱投影 + `drawAtlas` 销钉）、梳齿阻尼动画、光斑与光晕（着色器）、孔洞内阴影、纸屑粒子、暗角。
- 图集纹理：控制总大小；`@2x`/`@3x` 视内屏 / 外屏分别提供。

### 8.3 动画与手势

- **Reanimated（版本以 `expo install` 对 SDK 58 解析的为准）+ `react-native-worklets`**。全部连续动画都在 UI 线程。
- 铰链：`useAnimatedHinge()`（UI 线程共享值，不经 JS）。`L = f(θ)`，再 `withSpring(spring.lid)`。
- 手势：`react-native-gesture-handler`。钥匙的圆周手势用 `Pan` + `atan2` 计算角度增量。
- **JS 线程不参与每帧动画**：JS 只做状态机（姿态、曲目、睡眠）与调度器。

### 8.4 音频与触觉

#### 引擎选型

| 方案 | 优点 | 风险 | 结论 |
|---|---|---|---|
| **`react-native-audio-api`**（Web Audio 风格，原生音频线程） | 以 `AudioContext.currentTime` 精确定时；有滤波、卷积混响；Expo 插件处理后台音频 | 调度在 JS 里；离线渲染**未核实**；JS 线程抖动会影响 lookahead | **首选**，M0 做抖动测试 |
| `expo-audio` | 官方、锁屏控件、播放列表 | 不适合采样级的精确调度与滤波 | 仅用于次要音效（如闹钟预览）、锁屏控制（以实测为准） |
| **自写 Swift 模块**：`AVAudioEngine` + `AVAudioUnitSampler` + `AVAudioUnitReverb`/EQ | 样本级精度；原生后台稳定；可做离线渲染（闹钟音频） | 工作量大；非 RN 通用 | **Plan B**。AudioEngine 接口先抽象（`schedule(note, t)`、`setLowpass(hz)`、`setTempo(f)`），便于替换 |

#### 调度

- **lookahead 调度：** 每 100ms 计划未来 400ms 的音符（`source.start(when)`）。渐慢期间 lookahead 缩到 150ms，因为速度因子 `f` 在变。
- **音符事件 = 唯一真相：** 视觉（销钉、梳齿）、触觉、音频都从同一批事件派生。
- **触觉同步：** `CHHapticEngine.currentTime` 与音频时钟不同。做法：每首曲子预生成触觉图案（`CHHapticPattern`），启动时用绝对时间戳；首次安装时做一次**闭环校准**（音频 + 触觉同时触发，用麦克风与加速度计测相位差，存为固定偏移）；渐慢期间触觉也要按 `f` 重新生成（只对接下来 400ms）。
- **回退：** 如果同步达不到 ≤ 10ms，退一步用 Core Haptics 的 `audioCustom` 事件由同一个引擎播放音频 + 触觉（Apple 文档确认存在），代价是失去滤波与混响的灵活性。

#### 触觉模块

- 自写 Expo 模块（Swift，Expo Modules API）：`prepareEngine()`、`playPattern(events)`、`stop()`；生命周期跟随前后台；检测 `supportsHaptics`；引擎被系统停止后自动重启。
- `expo-haptics` 仅作为不支持 Core Haptics 设备的兜底（假设它只有预设，未重新核对）。

#### 时钟传递（JS → UI 线程）

- `AudioContext.currentTime` 在 JS 里读。**如何低延迟地把它交给 UI 线程我没有核实。** 方案：每 250ms 把 `(audioTime, hostTime)` 写入共享值，UI 线程用帧时间戳外推，并做漂移校正；M0 要测漂移是否 < 1 帧。

### 8.5 铰链与布局模块

- `useAnimatedHinge()`：驱动盖子 `L`、低通截止、视差；**不用来决定布局**。
- 姿态判定：`useReservedRegions()` 的 `division` region + 窗口尺寸；`PoseProvider` 暴露 `pose: 'closed' | 'tabletop' | 'book' | 'flat' | 'phone'`。
- 兜底：如果在外屏上收不到 `closed`（§5.1 未核实），用"窗口尺寸变为外屏尺寸 + hinge 为 null / unknown"判定为 A；渐慢仍由 θ 穿越 40° 触发（合盖的几百毫秒内应该有角度更新，**M0 实测**）。
- `expo-status-bar` 的竖向栏：保持默认（系统放），**不关闭**。
- 严格避免 `UIScreen.main` 与设备方向（Expo 已处理自家包）。

### 8.6 小组件、Live Activity、闹钟

| 能力 | 方案 | 备注 |
|---|---|---|
| 主屏 / 锁屏小组件（展示） | `expo-widgets` + `createWidget` | 小组件代码在隔离运行时，**所有数据通过 props**；图片写入 `widgetsDirectory`；声明 `isLuminanceReduced` 样式 |
| Live Activity / 灵动岛 | `expo-widgets` + `createLiveActivity` | 紧凑 / 展开 / 锁屏；更新用 `update()`；模拟器不可测 |
| 小组件播放 / 暂停 | **自写 Swift 小组件 target** + `AudioPlaybackIntent`（iOS 17+），经 config plugin 集成；与 App 通过 App Group 共享状态 | `expo-widgets` 的 `Button.onPress` 只返回 props，做不到。也可评估 alpha 的 `expo-app-intents` |
| 闹钟 | **AlarmKit**（iOS 26+）：`expo-alarm-kit`（社区）或自写薄模块；`NSAlarmKitUsageDescription` | 社区库的维护状态要评估。自写的好处是可以做倒计时 Live Activity |
| 通知回退 | `expo-notifications`（Duo 是 iOS 27，AlarmKit 一定可用；回退只为 iOS < 26 的 iPhone） | 本地通知声音上限 30 秒（既有认知，未重新核对） |

> **部署目标建议：iOS 26.0。** Duo 是 iOS 27，AlarmKit 一定可用。是否同时支持更低系统取决于 Expo SDK 58 的最低要求，**我没有核实**。

### 8.7 数据与分享

- **数据模型：** `Song { id, title{lang→string}, steps(≤192), tempoBpm, kind: 15|20|30, notes[{t,p,vel?}], case, createdAt }`。
- **存储：** 文件系统 JSON（`expo-file-system`），最多几百首，不需要数据库。
- **分享链接（P1）：** 曲子编码为紧凑二进制（每音符 1 字节 pitch + 1 字节 step，可 RLE），base64url 放在 URL hash（≈ 1.2KB 以内），**服务端不存储任何数据**。网页用 Web Audio 播放；OG 预览图可用边缘函数按 hash 生成（Cloudflare Workers 是候选，未决）。
- **视频（P0）：** 用同一渲染与离线合成导出，**不上传**。

## 12. 一次完整的体验走查（验收时逐步对照）

1. **安装后第一次打开**（外屏，A）：一个合着的盒子和一句"打开我"。暗示动作，无任何弹窗。
2. **展开到半折立放**（B）：盖子随角度连续抬起；角度到 15° 左右第一次有金属光；60° 时梳齿露出；到 85° 以上盖子"顿一下"并上发条动画；随后第一句旋律响起。第一次听到曲子的 60 秒内就应该完成**发条 → 听见**。
3. **听了三十秒**：拨一下梳齿能听到手拨音（弹簧回弹、触觉）；转动钥匙能上发条。
4. **折回外屏**：盒子回到外屏 A，状态一致，没有跳转，没有 Loading。
5. **全展开到工作台**（F）：盒子贴边；纸带在下方展开；打孔 / 擦除；左右手同时点两个格子，两个音同时响（多点触控）。
6. **睡眠**：选 30 分钟，合上盖子，音乐渐慢到静音；夜里在锁屏看到"八音盒 · 剩余 18 分钟"（P1）。
7. **闹钟**：选一首自己打的曲子作为明早的闹钟。
8. **分享**：导出 15s 视频，系统分享。
